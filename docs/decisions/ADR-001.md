# ADR-001: Request Status History and State Tracking

## Status
Accepted

## Context
The system requires real-time status tracking for requesters as well as auditability for operational metrics and SLA compliance. We needed to choose between simply overwriting the request state or maintaining an event-based history log.

## Decision
We will retain both current state attributes on the primary Request entity for fast query access AND record timestamped event entries in an immutable `AuditLog` table on every transition.

## Consequences
- **Positive:** Enables complete timeline visibility, SLA auditability, and clear operational reporting.
- **Negative:** Slightly increases storage overhead and requires dual writes on state transitions.
